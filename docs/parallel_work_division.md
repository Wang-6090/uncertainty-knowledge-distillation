# 三人并行实验工作划分

## 1. 工作目标

本轮工作围绕一个核心问题展开：在训练阶段没有未知类别标注的条件下，如何提高未知样本检测和后续新类别聚类的可靠性。

项目流程可以拆成三个相互衔接、但能够并行研究的环节：

1. 学习适合开放环境的分类表征，并判断不确定性知识蒸馏是否真正带来额外收益；
2. 利用分类表征估计未知风险，筛选可靠的未知候选样本；
3. 在候选池固定后组织新类别聚类，并区分拒识误差与聚类误差。

三个人可以同时开展第一轮工作。每个人先使用统一的正式协议和固定基线完成自己的研究线，不需要等待另外两个人的实验。只有进行最终完整流程验证时，才交换已经确认的配置和结果。

## 2. 三人分工总览

| 成员 | 负责部分 | 要回答的主要问题 |
|---|---|---|
| 王笑颜（负责人） | 分类表征与不确定性知识蒸馏 | 不确定性加权蒸馏是否改善学生模型表征，并能否为后续未知检测提供更好的输入？ |
| 李柯颖 | 未知风险估计与候选筛选 | 当前未知检测不稳定主要来自风险分数、阈值，还是拒识器的表征配置？ |
| 齐誉涵 | 候选特征与新类别聚类 | 候选池固定后，聚类误差主要来自候选污染、特征表示、降维、聚类方法还是类别数估计？ |

## 3. 共同遵守的实验协议

三个人使用相同的正式设置，避免因为数据和评价方式不同而无法比较：

- 数据集：CIFAR-100；
- 基础类别划分：60 个已知类别、40 个未知类别；
- 划分文件：`splits/cifar100_60_40.json`；
- 教师模型：ResNet-34；
- 学生模型：ResNet-18；
- 正式随机种子：`42`、`123`、`3407`；
- 默认开放风险分数：`normalized_entropy_mahalanobis`；
- 未知类别标签不用于训练、模型选择或阈值校准，只在最终评价阶段计算指标。

如果使用 `semantic_hard` 等难度更高的类别划分，必须单独标明协议名称，不能与基础 60/40 结果混在同一张主表中。每次实验都要记录类别划分、随机种子、模型配置、训练轮数、阈值策略和聚类设置。

## 4. 并行开展方式

每个人先完成以下共同准备工作：

1. 确认正式划分文件能够正常读取，并核对已知类别、未知类别数量；
2. 使用最小配置跑通本人负责环节；
3. 保存实际运行命令、配置文件、原始指标和运行日志；
4. 将实验结果写入各自目录，避免覆盖其他人的中间结果；
5. 第一轮只使用固定基线，不因为其他人的实验尚未完成而暂停。

建议使用以下结果目录：

```text
runs/team_a_representation/
runs/team_b_rejection/
runs/team_c_clustering/

analysis/team_a_representation/
analysis/team_b_rejection/
analysis/team_c_clustering/
```

每条研究线都要先完成“最小基线—单因素对照—结果判断”，只有结果支持新的研究假设时，才能进入下一轮扩展。

## 5. 王笑颜：分类表征与不确定性知识蒸馏

### 5.1 负责的研究问题

本部分研究学生模型如何获得分类表征，以及不确定性信息加入知识蒸馏后是否真正改变了表征质量。需要区分两个问题：

- standard-KD 相比只使用交叉熵，是否改善学生模型；
- uncertainty-KD 相比 standard-KD，是否带来额外且稳定的收益。

不能直接把完整模型的变化全部归因于不确定性蒸馏，必须通过逐步对照定位作用来源。

### 5.2 具体工作一：确认基础训练流程

先确认教师模型和学生模型的训练流程能够独立运行：

1. 使用 ResNet-34 教师模型输出类别 logits 或软类别分布；
2. 使用 ResNet-18 学生模型完成已知类别分类；
3. 检查学生模型是否能够保存分类 logits、分类特征和不确定性相关输出；
4. 确认训练阶段没有读取未知类别标签；
5. 保存一组能够复现的基础训练日志和 checkpoint。

这一阶段不追求提高指标，目的是确认后续拒识和聚类使用的特征确实来自当前学生模型，并且训练流程没有发生标签泄漏。

### 5.3 具体工作二：完成三组核心对照

第一轮只比较以下三种训练目标：

| 方案 | 训练目标 | 需要回答的问题 |
|---|---|---|
| A | CE | 只用已知类别标签时，学生模型的基础表现如何？ |
| B | CE + standard-KD | 教师的软类别分布是否改善学生表征？ |
| C | CE + uncertainty-weighted KD | 根据样本不确定性调整蒸馏强度是否比 standard-KD 更有效？ |

三组实验必须固定数据划分、教师模型、学生模型结构、优化器、学习率、训练轮数、batch size、数据增强和随机种子。除了训练目标，不同时改变模型结构或后续拒识配置。

比较时至少记录：

- 已知类别分类准确率；
- 学生分类特征的类内紧凑性和类间分离情况；
- AUROC、AUPR、FPR95、OSCR；
- 已知接受率、未知拒识率；
- 候选池召回率、候选池纯度和已知污染率；
- ACC、NMI、ARI 等聚类指标。

A 与 B 用来判断知识蒸馏本身是否有作用，B 与 C 用来判断不确定性加权是否有额外作用。不能只看分类准确率，也不能只看某一个随机种子的 AUROC。

### 5.4 具体工作三：审计不确定性蒸馏是否真实生效

如果 C 相比 B 出现改善，需要进一步确认改善确实来自不确定性蒸馏，而不是配置差异或随机波动。需要检查：

1. 教师不确定性信号来自哪个输出，例如预测熵、置信度或不确定性头；
2. 不确定性如何转换为蒸馏权重；
3. 高不确定性和低不确定性样本的蒸馏权重是否实际不同；
4. uncertainty-KD 损失是否参与总损失；
5. 该损失是否产生非零梯度，并更新学生模型参数；
6. 训练日志中的权重、损失和梯度是否与配置一致。

如果审计不能证明机制实际参与优化，先修复训练或记录问题，不能继续扩大实验规模。

### 5.5 具体工作四：有依据时再扩展

只有 B-C 在三个正式种子中呈现可解释的方向性信号，才继续以下扩展，并且每次只加入一个因素：

- feature KD：比较教师特征迁移是否进一步改善学生特征；
- uncertainty head：比较显式不确定性输出是否有额外作用；
- SupCon 或 prototype：比较类内紧凑和类间分离约束的作用。

如果 C 相比 B 没有稳定方向，停止不确定性权重扫描，并将结果记录为“当前设置下未观察到稳定收益”。

### 5.6 交付结果

需要提交：

- A、B、C 三组配置和实际运行命令；
- 三个正式种子的原始指标和均值/标准差；
- 不确定性权重、损失和梯度审计结果；
- 分类特征的简单分布或类间距离分析；
- 一份结论，明确说明 standard-KD 和 uncertainty-KD 分别改变了什么，以及是否值得继续。

## 6. 李柯颖：未知风险估计与候选筛选

### 6.1 负责的研究问题

本部分在学生分类表征固定的情况下，研究未知样本如何被识别和筛选。重点区分三个可能来源：

- 风险分数不能有效区分已知和未知；
- 已知验证集确定的阈值不稳定；
- 拒识器本身的表征或初始化方式不合适。

本部分不修改学生蒸馏目标，也不调整后续聚类算法。

### 6.2 具体工作一：跑通固定风险分数和阈值流程

先固定学生模型和默认风险分数 `normalized_entropy_mahalanobis`，完成以下检查：

1. 提取已知验证样本和测试样本的风险分数；
2. 记录风险分数的分布、范围和已知样本之间的重叠；
3. 明确阈值由哪些已知验证集统计量确定；
4. 记录每个正式种子的实际阈值数值；
5. 统计已知接受率、未知拒识率和候选样本数量；
6. 统计候选池中的未知召回率、候选纯度和已知污染率；
7. 检查阈值附近样本在三个种子中的候选标记是否变化。

这一阶段回答“当前不稳定是否主要来自风险分数和阈值”。阈值只能使用已知验证集确定，不能通过测试集未知标签寻找最优工作点。

### 6.3 具体工作二：比较两种拒识器配置

在学生模型、风险分数、阈值校准、训练轮数和评价方式完全相同的条件下，只改变拒识器配置：

- `scratch_cnn`：使用独立的轻量 CNN 拒识器，从随机参数开始训练；
- `shared_backbone`：使用独立的拒识器，以学生分类主干参数初始化。

需要先说明这两个配置都用于估计未知风险，比较目的不是比较两个分类器，而是判断拒识器的初始化和表征来源是否影响：

1. 已知/未知风险分数的排序；
2. AUROC、AUPR、FPR95 和 OSCR；
3. 阈值附近样本的稳定性；
4. 候选池未知召回率；
5. 候选池纯度和已知污染率；
6. 不同正式种子之间的结果波动。

如果 shared-backbone 只在单个种子或单个指标改善，结论应写成局部信号，不能直接认定初始化方案稳定有效。

### 6.4 具体工作三：有明确依据时验证 NNPU

只有在前两步确认发现池中同时存在已知和未知样本，并且将整个未标注池直接当作未知类会造成错误监督时，才验证 NNPU。

NNPU 是 Non-Negative Positive-Unlabeled learning，即非负正类—未标注学习。具体设置是：

- 已知类别样本作为有标签的一侧；
- 可能同时含有已知和未知样本的发现池作为未标注一侧；
- 通过非负风险估计减少把未标注样本全部当成未知类所带来的错误监督。

NNPU 实验只固定一组先验比例、损失权重和训练配置，按三个正式种子验证，不进行大规模参数扫描。需要比较 NNPU 与当前拒识器配置在候选召回率、候选纯度、已知污染率和聚类结果上的变化。如果 NNPU 只提高召回率但明显降低纯度，不能直接替换默认流程。

### 6.5 具体工作四：定位候选池误差

对候选池中的错误进行分解：

1. 未知样本没有进入候选池，属于候选漏检；
2. 已知样本进入候选池，属于候选污染；
3. 样本风险分数正确，但阈值附近发生跨种子波动；
4. 候选池可靠，但后续聚类仍然无法分开。

需要输出按类别统计的候选数量和污染情况，判断问题是否集中在少数语义相近类别，而不是只报告总体拒识率。

### 6.6 交付结果

需要提交：

- 固定风险分数和阈值的基线结果；
- `scratch_cnn` 与 `shared_backbone` 的成对对照；
- 三个正式种子的风险分数、阈值和候选池统计；
- 阈值附近样本的稳定性分析；
- 只有在有监督混合依据时才提交 NNPU 对照；
- 一份结论，明确问题主要来自风险排序、阈值、拒识器还是候选池污染。

## 7. 齐誉涵：候选特征与新类别聚类

### 7.1 负责的研究问题

本部分不重新调整拒识阈值，而是在候选池固定后研究新类别聚类。需要区分：

- 候选池本身污染导致聚类困难；
- 分类特征或投影特征不适合区分新类别；
- PCA 降维损失了有用信息；
- KMeans 等聚类方法不适合当前特征分布；
- 自动估计类别数产生额外误差。

### 7.2 具体工作一：固定候选池并检查输入

候选池生成后立即冻结，后续聚类实验不能因为聚类指标变化而重新调整候选样本。候选池文件至少保存：

- 样本索引；
- 分类特征和投影特征；
- 风险分数；
- 候选标记；
- 模型、划分、种子和阈值配置。

未知标签只能在最后评价阶段读取，不能作为聚类输入或方法选择依据。

### 7.3 具体工作二：使用 oracle K 建立聚类基线

第一轮使用 oracle K，即在评测阶段使用真实未知类别数量作为聚类簇数。这样可以先排除“类别数估计错误”的影响，单独检查特征和聚类方法。

依次进行以下单因素比较：

1. `feature_pca + KMeans`：分类特征先经 PCA，再使用 KMeans；
2. `projection_pca + KMeans`：比较投影特征是否更适合聚类；
3. `feature + KMeans`：判断 PCA 是否造成信息损失；
4. 在最稳定的特征上比较 KMeans、Agglomerative 和 Spectral。

每次只改变一个因素，不同时改变特征形式、PCA 维度、聚类算法和 K。每个对照都要记录 ACC、NMI、ARI、簇大小分布以及每个未知类别的候选数量。

### 7.4 具体工作三：分析候选池和聚类误差

使用候选池结果和聚类结果进行误差分解：

- 如果全部真实未知样本在 oracle K 下聚类仍然较差，重点是特征可分性或语义相似类别重叠；
- 如果全部未知样本聚类较好，但拒识候选池聚类较差，重点是候选漏检或候选污染；
- 如果候选池在 oracle K 下较好，但 auto K 结果变差，重点是类别数估计。

需要给出按类别统计的候选数量、候选污染率、簇大小和每类聚类表现，不能只给出一个总体 ACC。

### 7.5 具体工作四：最后再研究自动类别数

只有 oracle K 下已经得到可解释结果后，才研究 `auto K`。需要记录：

1. 自动选择的类别数；
2. 真实未知类别数；
3. 类别数绝对误差；
4. 自动选择规则；
5. auto K 与 oracle K 的 ACC、NMI、ARI 变化。

如果 auto K 变差是因为候选池污染，优先报告候选池问题，不通过扩大 K 搜索掩盖拒识阶段的问题。

### 7.6 交付结果

需要提交：

- 冻结候选池文件；
- 分类特征、投影特征和 PCA 配置；
- oracle K 下的特征/聚类方法对照；
- 必要时的 auto K 对照；
- ACC、NMI、ARI、候选污染率、簇大小和类别级统计；
- 一份结论，明确聚类瓶颈来自候选池、特征、降维、聚类方法还是类别数估计。

## 8. 三条线的并行进度

| 阶段 | 王笑颜：表征蒸馏 | 李柯颖：未知拒识 | 齐誉涵：候选聚类 |
|---|---|---|---|
| 启动 | 跑通教师—学生训练和 A/B/C 配置 | 跑通固定学生模型、风险分数和阈值 | 读取或生成固定候选池并检查特征 |
| 第一轮 | 完成 CE、standard-KD、uncertainty-KD 三种子对照 | 完成风险分数和阈值稳定性分析 | 完成 oracle K 下的特征形式对照 |
| 第二轮 | B-C 有方向性信号才扩展 feature KD 等模块 | 有明确信号才比较两种拒识器；再判断是否需要 NNPU | 有明确信号才比较聚类算法；再判断是否需要 auto K |
| 独立总结 | 判断不确定性蒸馏是否值得继续 | 定位风险、阈值或候选污染问题 | 定位特征、聚类或类别数问题 |
| 最终协作 | 提供确认的学生配置 | 提供确认的拒识配置 | 提供确认的聚类配置 |

三个人的第一轮可以同时开始、分别结束。任何一条线因计算或复核暂缓，其他两条线继续推进；最终完整流程只使用三条线已经确认的配置重新运行。

## 9. 统一记录格式

每次实验保存：

```text
config.json       # 数据划分、模型、损失、阈值、聚类和随机种子
command.txt       # 实际执行的完整命令
metrics.json      # 各种子的原始指标
summary.md        # 研究问题、对照关系、数据变化和结论
```

每份 `summary.md` 必须回答：

1. 本次只改变了什么；
2. 与哪个正式基线比较；
3. 分类、检测、候选池和聚类指标如何变化；
4. 变化是否在三个正式种子中保持同一方向；
5. 结果支持、削弱还是尚不足以支持原研究假设；
6. 下一步是否值得继续，以及继续的具体依据。

## 10. 统一停止规则

出现以下情况时停止该方向扩展并保留负结果：

1. 只是继续扫描参数，没有新增研究问题；
2. 只在单个种子或单个指标上改善；
3. 一个指标改善，但已知污染率、FPR95 或聚类质量明显恶化；
4. 必须使用测试集未知标签才能选择参数；
