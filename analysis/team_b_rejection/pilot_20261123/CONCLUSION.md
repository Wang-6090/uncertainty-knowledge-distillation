从这四条 pilot 结果可以确认的是**审计工具自身在工作**，不是方法效果：

1. **阈值确实存在可测量的抽样波动**：同一份协议下阈值从 1.3874 到 1.7270（跨度 0.34），
   自助法 std 0.062–0.070。这说明 6.2 要求的"每个种子的阈值数值 + 阈值稳定性"
   必须逐种子报告，不能只报一个数字。
2. **翻转样本集中在阈值邻域**：邻域内候选标记翻转率 0.408–0.424，
   邻域外只有 0.045–0.054，翻转样本距阈值平均 1.02，稳定样本平均 1.53。
   这是 6.2-7 想要的那种"阈值附近样本跨种子标记变化"的定量证据。
3. **误差分解能把三类上游损失分开**：pilot 里未知漏检占未知样本 93.5%–93.8%，
   已知污染占已知样本 4.7%–5.6%，被自动判为 `dominant_upstream_loss = unknown_missed`。
   这个判断和"学生只训了 2 个 epoch"是自洽的，可以反证分解逻辑没有写反。
4. **默认候选模式下"池召回"与"未知拒识率"是同一个量**（候选池 = 分数高于阈值的全部样本），
   两者只在启用 `--candidate-purify` 后才会分开。正式报告里不要当成两个独立证据。

## 6. 正式实验后应当怎么读结果（判据已固定，先写在这里避免事后解释）

1. 若 **AUROC / AUPR / FPR95 / OSCR** 在三个种子上方向一致，且候选池纯度、已知污染率不同向恶化，
   才可写"该拒识器配置稳定改善了未知风险排序"；
2. 若 **AUROC 不显著但阈值跨度大**（参照 pilot 的 0.34），结论应指向"阈值不稳定"而非"分数无效"；
3. 若 **候选池纯度低而候选池内聚类指标高**，说明瓶颈在拒识阶段（漏检/污染），
   不能把问题推给聚类方法；
4. 若 **NNPU 只提高召回、明显降低纯度**，保留默认流程并把 NNPU 记为负结果。
